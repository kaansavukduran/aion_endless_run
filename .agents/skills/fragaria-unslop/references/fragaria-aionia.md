# Fragaria Interactive and AIONIA

Read this profile when the active project belongs to Fragaria Interactive or the user asks to apply AIONIA standards. Fragaria Interactive is the publishing brand and AIONIA is the fictional universe. The design and QA standard also applies to independent digital products when requested. Match the project. Preserve approved brand artwork and character variants. Use the art bible for pixel density, palette, sprite pivots and animation. Keep proposed lore in draft status and distinguish reference sheets from approved in-game assets.

The private reference index identified in the active task points to project-specific and art sources. Limit connector reads to relevant material and keep private links and excerpts out of public project output. - Section 22 and its AIO-UI-001–005 and AIO-QA-001–003 IDs cover short panels, scroll, reachability and learning from complaints. For any recurrent issue, find the existing QA item or suite. Record the symptom, source, repro, expected result, evidence and environment there if scoped edits call for it. Preserve historical status, distinguish root cause from hypothesis, and add or update the relevant regression rather than duplicating records.
- For AIONIA games, apply the current standard's full gamepad flow. For phone and tablet targets, verify complete touch-only play in portrait and landscape with state preserved on rotation. Track physical devices and controllers separately from emulation. Follow the active game's control map, approved Fragaria branding, loading-state contract, and art direction. Use the existing approved control scheme and route any proposed change through the live standard’s control-choice protocol. Use the approved loading reference and real build label. Display a percentage only when actual progress is measurable. Keep gameplay state, previous saves and input bindings through UI changes.

## Art direction, characters, and branded loading

- For an AIONIA world or game, preserve the project's art bible and its sevimli, derin, epik direction. Assess a representative scene at normal play scale for silhouette, visual hierarchy, palette, lighting, pixel density or model proportions, and the fit between characters, world, effects, HUD and motion. Preserve deliberate accents, environmental storytelling and expressive animation when they support play and identity. Simplify repeated decoration and clutter that obscure the focus or the action. Use pixel art when the project calls for it. For 3D or another approved style, use the project's own art rules.
- For an in-scope character, match the current reference index and project canon by stable identity where recorded. Keep Aion, Baykuş Ömer, Tavşan Eren and Tavşan Emre distinct. Keep separate evidence for canon membership, approved design variant, and playable asset readiness. The index is open to future characters. Read its current entries and the project's approved references at use time, and use only characters relevant to the project and request. Preserve distinguishing features and compare the actual in-game representation against the approved source. If a source or approval is missing, preserve the current approved presentation and report the gap. Label proposed assets or lore as drafts until approved.
- For a Fragaria-branded game's opening or loading screen in scope, consult the current loading section of the standard and the approved project reference. Verify the dark composition, centered pixel-art strawberry and Fragaria Interactive lettering when the approved reference supports them, readable segmented loading indicator, and actual build version. Check the intended contrast and composition in the supported orientations. Treat artwork style approval and final logo approval separately. Bind the percentage to measurable progress or show an indeterminate state. Observe loading, failure/retry and the handoff into play in the target build where available.
- Apply these checks only to the relevant surfaces. For independent products using the AIONIA quality standard, use the product's own visual language and character scope.

## Explicit game-local variants

An approved new game-local character variant does not silently rewrite the shared universe's reference archive. Preserve the original artwork and identity records, record the requested variant and playable roster separately, and migrate old saved character keys deliberately. A retired playable character may remain an approved assist asset. Read [the current project contract](project-contract.md); historical references to the old roster do not override a newer explicit user request.
