# Sprite sheets and unintended motion

## Prepare frames

- For in-scope 2D frame-by-frame art, use the project's approved sprite sheet or atlas and its character references. Use the existing frame pipeline. If producing a new sheet is in scope, use the approved design to create distinct poses and stage a reviewable sheet. Preserve silhouette, proportions, palette and distinguishing marks. A turnaround or T-pose sheet is a design reference. Report missing animation frames and the actual production or approval status. Preserve approved rigged animation pipelines where they apply.
- Define each clip's action, directions, frame rectangles, playback order and timing, loop mode, and contact or body anchor. Follow the project's grid, resolution and scale. For cropped atlas frames, preserve original frame size and trim offsets or equivalent pivot metadata. Inspect margins, transparent padding, flipped directions, texture filtering and neighboring-frame bleed where relevant. Use the intended holds and pose changes. Count repeated stills as held frames.
- Use a stable actor origin for physics. Align grounded poses to a shared ground reference and the intended planted foot for each contact phase. Use a stable body reference for stationary airborne or flying poses. Measure a meaningful landmark or an authored anchor, since changing wing, tail, or silhouette bounds can shift an image centroid legitimately. Anchor shadows, collision and attachments according to their own gameplay contracts.

## Identify and verify the cause

1. Reproduce with no movement input on stable ground, or in a stationary flight state where supported. Step through a full loop including last-to-first. Record frame index, actor world transform and a visible landmark in actor-relative coordinates. Use a fixed camera or project onto world coordinates if the camera tracks the actor.
2. If world position drifts, trace input deadzone, velocity, collision, parent transforms and animation tracks writing the actor transform. If actor position holds and the landmark shifts unexpectedly, inspect crop, trim, offsets, pivot and flip. If both hold and only the rendered view jitters, inspect camera smoothing, rounding and project-specific pixel snapping at the target scale. Fix the responsible layer and keep intentional movement, body motion and authored root motion within their design contract.
3. Verify no-input idle, start and stop, facing changes, grounded walk/run contacts, and jump/land or flight transitions where supported. For moving clips compare foot contact against expected speed and animation timing. For hit or weapon animations check attachment and collision alignment and verify existing attack timing. Test the actual configured playback and view it at game scale. A sheet preview can establish alignment evidence. In-game transitions and presentation require runtime checks.
4. For recurring drift, preserve a regression that fails on the original defect and passes after the fix when practical. Assert world position independently from frame alignment, use the project's tolerances, and keep evidence for representative frames and the loop seam. Report any target build or device check that could not run.
